# LogFire — How To Use

## 1. Hub (Node-RED)

The Node-RED flow handles the server side — receiving messages, parsing them, storing them per device, and serving the browser UI.

`nodered/build.py` embeds `logfireUI.html` and the JavaScript sources in
`nodered/functions/` into `flow.json`, so the imported flow is self-contained.
Run it before importing, and again whenever either source area changes:

```bash
python nodered/build.py
```

Treat `logfireUI.html` and `nodered/functions/*.js` as the source files. The
corresponding Function-node code inside `flow.json` is generated by this command.

Then import `nodered/flow.json` into Node-RED via the hamburger menu → **Import**. After deploying, open `http://<host>:<port>/logfire` in your browser. A test log fires automatically on deploy so you can confirm it's working before connecting any device.

The flow uses HTTP paths `/log`, `/logs`, `/devices`, `/clear`, `/logfire`,
WebSocket path `/ws/logs`, and UDP port `1880`. Update the existing LogFire flow
instead of deploying a second copy; other flows using these same paths or UDP
port on the instance will conflict.

Logs are stored in `/data/logfire_logs.json` inside the Docker container and loaded back on restart. The hub attempts to save pending changes every two seconds, using a temporary file before replacing the saved snapshot. An unexpected stop can lose changes since the last successful save; the interval is not a guaranteed limit on data loss. On an orderly stop or redeploy, the hub also attempts a synchronous save of pending changes, including any snapshot still being written. A failed final save is reported in the Node-RED log. An HTTP success response acknowledges receipt, not a completed disk write. Each device's log is capped at 3 MB — when it fills up, the oldest entries are dropped. Device count is not capped, so this is not a limit on total hub memory.

Saved logs also survive flow updates and redeploys. To start clean for a device,
select its tab in the UI and click **Clear**, or use `POST /clear` below.

### Hub API

HTTP and WebSocket endpoints use the Node-RED host and HTTP port (default `1880`).

| Endpoint | Request and result |
| --- | --- |
| `POST /log` | `Content-Type: text/plain`, body `DEVICE: message` or `DEVICE(-N): message` (`N` = 1–4). Returns `200 OK`; invalid input returns `400` with `Bad format. Expected DEVICE: message` or `Invalid device name`. |
| `GET /logs` | JSON object `{ "DEVICE": [{ "id": "…", "device": "DEVICE", "message": "…", "timestamp": "…", "level": 0 }] }` containing retained logs for all devices. There is no device filter; `?device=…` is ignored. |
| `GET /devices` | JSON array of device names. |
| `POST /clear` | `Content-Type: application/json`, body `{"device":"NAME"}`. Deletes that device's retained logs; returns `200 OK`, `400 Missing device` for a missing/empty/non-string name, or `503 Log store is starting` during startup. |
| `GET /logfire` | Browser UI. |
| WebSocket `/ws/logs` | One JSON log entry per live message, with the same fields as `/logs` entries. |
| UDP port `1880` | Same plain-text format as `POST /log`, one message per datagram; no response. |

Device names are trimmed and must be nonempty, at most 64 JavaScript string
code units long, and contain no control characters. `__proto__`, `constructor`,
and `prototype` are reserved names. Messages may contain newlines.

### Docker port mapping

The default clients (`LogFire`, `logfire.py`) use HTTP over TCP. The UDP clients
(`LogFireUDP`, `logfire_udp.py`) send to the flow's UDP listener on the same port
number, so expose `1880/udp` only when you use them. The UDP input is a core
Node-RED node, so it does not require a Node-RED reinstall.

If the hub runs in Docker, adding UDP normally requires recreating the container
with an explicit UDP mapping. Export all active flows and verify that the
`/data` volume is persistent before recreating it. Replace `192.168.1.10` below
with the Node-RED host's LAN address:

```yaml
ports:
  - "192.168.1.10:1880:1880/tcp"
  - "192.168.1.10:1880:1880/udp"
```

For a new hub, use a named volume with `docker run`. Node-RED 5.0.10 is the
tested version:

```bash
docker run -d --name logfire --restart unless-stopped \
  -v logfire-data:/data \
  -p 192.168.1.10:1880:1880/tcp \
  -p 192.168.1.10:1880:1880/udp \
  docker.io/nodered/node-red:5.0.10
```

Reuse this volume when recreating the container. For an existing hub, retain its
current `/data` mount or migrate its contents first; a new volume starts empty.

Open `http://192.168.1.10:1880/logfire` using your chosen LAN address. For local
tests published to loopback, use `127.0.0.1`: with rootless Podman, `localhost`
may resolve to IPv6 `::1`, which that mapping does not forward.

If a firewall is enabled, allow TCP port `1880` from your trusted LAN. Allow
UDP port `1880` only when using UDP clients. Container port publishing and
firewall rules must both permit the traffic.

Do not forward port `1880` on the router or expose it to the public internet.

## 2. Arduino (ESP32 / ESP8266)

`arduino/LogFire/` is a standard Arduino library. Copy it into your PlatformIO project's `lib/` directory, or into `~/Arduino/libraries/` for the Arduino IDE.

Include the header and call `begin()` once in `setup()`, after WiFi is already connected. Pass it a device name (labels the tab in the UI), the IP of your Node-RED host, and the port (default 1880).

```cpp
#include <LogFire.h>

LogFire.begin("DeviceName", "10.0.0.XX", 1880);
```

Then call `log()` anywhere:

```cpp
LogFire.log("your message here");           // level 0 (plain)
LogFire.log("something is off", 2);         // level 2 (WARN — yellow)
LogFire.log("something broke", 3);          // level 3 (ERROR — red)
```

Log levels: 0 = plain (default), 1 = INFO (green), 2 = WARN (yellow), 3 = ERROR (red), 4 = CRITICAL (purple).

Each `log()` call also prints to Serial by default, so you don't lose your existing Serial workflow. To disable:

```cpp
LogFire.mirrorSerial(false);
```

For Serial-only logging without network traffic (useful during development without a hub):

```cpp
LogFire.localOnly(true);
```

The client keeps one connection open between calls. Hubs may close idle
connections; the client makes one reconnect and resend when a reused
connection fails, with no retry after a fresh connection fails. A resend can
duplicate a message if the hub received it but the response was lost.
The client sets a one-second response timeout and, on ESP32, a one-second
connection timeout. These are not a total limit on `log()`: name resolution,
network operations and a retry
can add time. Use `localOnly(true)`, the UDP variant below, or avoid network
logging in time-critical code.

### UDP variant (experimental)

`LogFireUDP` has the same API but sends each message as a single UDP packet without
waiting for a hub response. Packets can be lost, duplicated or reordered. DNS
lookup and socket operations can still take time; this is not a guaranteed
nonblocking API. The hub must expose `1880/udp` (see Docker port mapping).

```cpp
#include <LogFireUDP.h>

LogFireUDP.begin("DeviceName", "10.0.0.XX", 1880);
LogFireUDP.log("something is off", 2);
// LogFireUDP.mirrorSerial(false);
// LogFireUDP.localOnly(true);
```

If WiFi is not connected, the network send is skipped. Serial mirroring follows
the `mirrorSerial` setting.

See [`arduino/LogFire/examples/`](arduino/LogFire/examples/) for full working examples
(`arduinoIDE/` and `platformio/` for TCP, `arduinoIDE_UDP/` for UDP).

## 3. MicroPython (Pico W / Pico W2)

`logfire.py` is a single-file module — copy it alongside your `main.py`. It handles WiFi sends and REPL mirroring with no dependencies beyond the standard MicroPython libraries.

Call `init()` once at boot after WiFi is connected:

```python
import logfire

logfire.init("DeviceName", "10.0.0.XX", 1880)
```

Then call `log()` anywhere:

```python
logfire.log("your message here")            # level 0 (plain)
logfire.log("something is off", 2)          # level 2 (WARN — yellow)
logfire.log("something broke", 3)           # level 3 (ERROR — red)
```

Log levels: 0 = plain (default), 1 = INFO (green), 2 = WARN (yellow), 3 = ERROR (red), 4 = CRITICAL (purple).

Each `log()` call also prints to the REPL by default. To disable:

```python
logfire.mirror_serial(False)
```

For Serial-only logging without network traffic:

```python
logfire.local_only(True)
```

The module keeps one connection open and reads every response completely. After
more than four seconds idle, it opens a fresh connection before sending the next
message. If an attempt on a reused connection fails, it reconnects and resends
once; this can duplicate a message if only the response was lost. If an attempt
on a fresh connection fails, the message is discarded. Socket operations use a
five-second timeout, which is not a total limit on the duration of `log()`.

### UDP variant (experimental)

`logfire_udp.py` has the same API (`init`, `log`, `mirror_serial`, `local_only`)
and sends each message as one UDP packet without waiting for a hub response.
The same delivery and timing limitations as the Arduino UDP client apply.
Copy it instead of, or next to, `logfire.py`:

```python
import logfire_udp

logfire_udp.init("DeviceName", "10.0.0.XX", 1880)
logfire_udp.log("something is off", 2)
```

See [`micropython/example/main.py`](micropython/example/main.py) (TCP) and
[`micropython/example/main_udp.py`](micropython/example/main_udp.py) (UDP) for full working examples.

### Testing without a Pico

`micropython/test_logfire.py` runs both clients on standard Python. Without
arguments it runs the unit tests. With `--live` it also sends to a running hub and
checks delivery via `/logs`. Pass the hub address with `--host`; `--port`
defaults to `1880` and applies to both HTTP and UDP. Run from the repository root:

```bash
python micropython/test_logfire.py --live --host 192.168.1.10 --port 1880
```

Hub, browser and connection tests against a disposable Node-RED container are
described in [`tests/README.md`](tests/README.md).
